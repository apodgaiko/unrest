# v0.4.6 measurement helpers

These provider-free tools are research infrastructure. They do not enable or
optimize product dispatch. The mission's frozen protocol remains authoritative.
The initial ruler requires parent review before candidate work.

`measure_v046_startup.py --python /absolute/python --install editable
--case-manifest cases.json --output results.json --ledger launches.jsonl`
executes the matching isolated install matrix. Select `--load concurrent-4`
for grouped guardrails. Use `--case` and `--samples` for
explicit subsets. The total concurrent launch count must divide by four; ten repeats across
twelve cases per installation creates thirty groups with no omitted case. A diagnostic
may capture an unreviewed catalog with `--diagnostic`; it still consumes launch
budget and cannot stand in for independently reviewed schema correctness.

Every launch is reserved in the shared JSONL ledger before spawn, including
failures and diagnostics. An interrupted reservation is consumed. Import the
fixture lane's reported launches once with `ledger_event`, kind `external`,
source bound to its READY digest. The approved 2300 cumulative ceiling applies across every task.
Never start a new ledger to reset the campaign allowance.

The full matrix is 4 roles × 3 homes × 2 installs × 2 load conditions. Scored
runs require the parent approval file's exact digest, the frozen fixture file
inventory, and exact role catalogs. No array sorting or schema normalization is
allowed. Empty means no historical workload; it includes the required tiny
planning-state probe for `inspect_project`. Seeded adds exactly ten completed
projects generated by `prepare_v046_fixture.py`, each with work/validate/gate
history. The preparation helper uses an explicit disposable home and local
in-process responses, never providers. The held-out fixture is separately owned;
its materialization/response oracle must be integrated only after approval.

The child uses an isolated Python interpreter, scrubbed environment, disposable
home and unique process group. MCP uses newline JSON-RPC with a 16 MiB reader
limit because the orchestrator catalog exceeds asyncio's default 64 KiB limit.
Each initialize/list/call has a ten-second deadline covering write, drain and
reply reads. The initialized notification and tools/list share one ten-second
phase deadline; a blocked notification cannot escape it. Normal shutdown has five seconds; forced reap and group disappearance each
have a separate five-second bound.
All roots in a concurrent batch are fully materialized, rebased, independently
checked and snapshotted before any measured spawn. Cleanup owns these roots
until all children finish. The batch has explicit barriers: finish every ledger
reservation (including fsync and helper/manifest hashes) and open every stderr
file before spawning; collect all replies or phase failures; verify every
response/catalog/handoff and pre-exit home; shut down all children concurrently;
only after the last cleanup finishes scan post-exit state, read/hash artifacts,
and persist results. No synchronous verification or persistence runs while a
peer awaits a reply or shutdown deadline. Failed peers join the same barriers;
a partial reservation failure spawns nothing and never refunds its prefix.
The verification barrier deliberately holds completed peers open. It is untimed,
and shutdown receives a separate `shutdown_start` timestamp immediately before
stdin close. Thus `shutdown` excludes peer reply waiting and pre-exit checking;
raw first-call-to-exit elapsed time includes both and is not shutdown latency.
Controlled task cancellation cancels reply collection once, waits for subprocess
creation and registration to settle, and drains independently owned shutdown tasks
before propagating cancellation. Repeated cancellation cannot cancel those owned
waits. Shutdown covers close errors, normal wait, forced kill/reap and group
checks. If bounded cleanup cannot confirm exit and group disappearance, the
sample fails, post-exit inspection is skipped, and its disposable root remains
for investigation. Interrupted reservations stay consumed. This protects task
cancellation while the controller runs; arbitrary OS hard-kill of the entire
controller cannot execute Python cleanup and is outside this guarantee.
Failures remain in the ledger and stop the current batch. Catalog, exact handoff,
fixture preservation, return code and process group cleanup are checked. Every
role must also match the independent structured response subset (strict boolean
`recorded: true` for completion roles). The approved first-call oracle is read
and hash-checked; empty/seeded orchestrator probes use their declared project/state.
Preservation is checked again after exit and process-group cleanup, including
handoff bytes. This check does not move the first-call/discovery timestamps.
Orchestrator startup may create only the two known foundation bootstrap files
(custody-root record and admission lock); every pre-existing fixture byte and
all other paths must remain unchanged.

Client monotonic timestamps measure spawn, initialize, tools list, first call
and exit. External instrumentation records aggregate server import, discovery,
policy support validation and role-server construction separately. These are
nested timings and must not be summed. Instrumentation changes no product
source bytes; both arms must use the same helper. OS caches are uncontrolled.
Package files and installed dependencies are hashed separately from timed
launches. The wheel omits source-only AGENTS.md; all shared package members must match.
The baseline identity must additionally bind the Git source inventory,
lock file, wheel bytes, effective environment template and helper hashes.

`calibrate` requires all 24 isolated cases with at least ten successful samples
each. It rejects failed/missing cases and computes nearest-rank p95, median,
MAD, noise=max(3×MAD,5ms), first-call tolerance=max(3×MAD,5ms), and discovery
p95 budget=p95+max(3×MAD,10ms). Proposed numbers require parent freeze; diagnostic
results do not establish them. Candidate confirmation and real desktop discovery
remain later independent work.

`measure_v046_flow.py --case-manifest flow-cases.json --mode simulated
--output flow.json` exercises the disabled pure model for all four arms against
explicit transition/count oracles. Its times and session IDs are symbolic.
It reports the fresh gate as pending and live benefit unmeasured. It does not
implement a coordinator, call providers, or claim integrated fixture bytes.
A later runtime helper extension must bind actual turns and fresh final gates;
live factorial execution requires an explicit new budget decision.
